# Glossary: every term the CSR8670 / SoundLink Micro project uses, defined the way the project uses it

Purpose: one place to look up a term, get a two-sentence definition, and follow a link to the file that holds the detail.
Status / last verified: 2026-10-10 (definitions re-checked against the cited files on this date; nothing here was observed on the device today). ROUND-3 AMENDMENT (2026-10-12, curator): corrections R3-C004, R3-C080 are appended at the end of this file (register: `docs/deep/round3-2026-10-12/README.md` section 4); the text above was not rewritten.
Read next: `docs/RESUME-HERE.md` (banner = current state), `docs/PROJECT-LAYOUT.md` (where files live), `docs/RETURN-CHECKLIST.md` (first day back).

> **This is an archival index from the original (larger, private) project repository**, kept here for provenance and detail. Many of its internal links (`docs/RESUME-HERE.md`, `docs/RETURN-CHECKLIST.md`, `docs/field-log.md`, `firmware/bose/probe/`, and others) point at files that are not included in this public export. `docs/CURRENT-STATE.md`, `docs/dsp-generator-route.md`, and `docs/ring-buffer-fix.md` are this export's own current, self-contained write-ups and are not affected.

Confidence marks follow the project convention: (proven) = address, instruction, command output or quoted press; (well-supported) = one traced inference beyond a proven fact; (hypothesis) = needs a press; (convention) = a naming or workflow usage, not a claim about the device; "unknown" = no source answers it, and the cell names the file that would. When two sources disagree the entry says so and says which is newer. Later entries and `docs/deep/offline-2026-10-10/verify.md` and `stack-transform.md` beat earlier text.

How to use it: find the term in the category index, jump to its letter (terms that start with a digit or a hex prefix, such as `0x1072`, `4022`, `40fe` and `262`, are under `## 0-9`), read the row, open the file in "read more". Entries cite repo files and memory notes only. A memory note is named like `memory csr8670-cave-window` and is kept machine-local, outside the repo. Where `docs/field-log.md` is the only source the entry cites the entry heading, for example `# probe173 -- RESULT`, not a line number.

## Address spaces (read this before quoting any address)

The project uses several incompatible number lines. Quoting an address without saying which one is the commonest source of error. Every address in these docs is one of the rows below unless it says otherwise.

| space | what it counts | how to convert | worked example (re-derivable) | where it comes from |
|---|---|---|---|---|
| code word address (written `a`, or `fn_NNNNN`, or "code word") | 16-bit words of `vm.app` code, counted from the first word AFTER the 24-word header | file word index minus 24; `file_offset = 0x12E97C + 2a` in the stock image | the hook is code word `0x00E46`; the cave entry is `0x3E21D` (proven, `build/hook/assemble_probe178.py`: `HOOK = 0x00E46`, `CAVE = 0x3E21D`) | `docs/trap-stub-table.md` header |
| data address (also "const address", "data space") | the VM's 16-bit data space; RAM globals sit below `0x7400`, and the flashed const pool is mapped in at `0x7400..0xD39A` | `data = 0x7400 + (a - 236514)` for a code word address `a` inside the const pool (const pool starts at code word 236514); inverse `a = 236514 + (data - 0x7400)` | the cave's TaskData lives at code words `CAVE+1, CAVE+2` = `0x3E21E`; `0x7400 + (0x3E21E - 236514)` = `0xBA3C`, the `TASK_ADDR` in the assembler (proven). RAM globals such as `@0x565` and `@0x570` are data addresses below `0x7400` | `docs/message-task-abi.md` section 4; `docs/deep/AGENT-BRIEF.md` |
| area byte offset (also "fs area byte", "area byte") | bytes counted from the start of the `fsr_dfu1` filesystem area inside a DFU file | area byte of low byte of code word `cw` = `AREA0 + 2*cw` with `AREA0 = 0x6EA30`; the high byte is `+1` | hook word `0x00E46`: `0x6EA30 + 2*0x0E46 + 1 = 0x706BD`, the first redirect byte (proven, matches `REDIRECT_EDITS` in the probe178 assembler). The fs body starts at area byte 140; `data_us` byte 0 is area byte 600 (`docs/deep/offline-2026-10-10/payload-184.md`) | `tools/fsedit.py` docstring |
| content offset | bytes counted from the 4-byte digest field, which is area byte 136 | content offset = area byte minus 136 | a byte is a blind byte (writable) when its content offset mod 64 is in 34..62 (`tools/fsedit.py` `blind()`) | `docs/deep/offline-2026-10-10/write-constraint.md` (a) |
| file byte offset | bytes into a whole `.dfu` or readback file | differs per file: `fsr_dfu1` sits at `0xbfc00` in one readback and `0xbff4c` in another | never compare readbacks with `cmp`; align on the `fsr_dfu1` marker first (proven) | `docs/FLASH-PROTOCOL.md` step 4 |
| stack word index | 16-bit words of `stack_prog.bin` (the BlueCore stack), as printed in `build/analysis/stack-disasm.txt` | the stack's runtime code address is the file word index + 10 (+ a bank) (well-supported); NEVER a `vm.app` address | the IMA ADPCM decode function is at stack word `0x059cec` (proven by instruction text, `docs/deep/offline-2026-10-10/stack-transform.md`) | header of `stack-disasm.txt`; `docs/deep/AGENT-BRIEF.md` |
| Kalimba PM / DM address | program memory (PM) and data memory (DM) of the Kalimba DSP images (`.kap`) | independent of everything above; a `.kap` also has a PM-flash overlay at `0x3000+` | `sbc_decoder` registrar at PM `0x349c`; the `0x1072` handler at PM `0x1768`; the `cbops.shift` fields at DM `0x29e6` and `0x29cc` (proven, `docs/kalimba-disasm.md`) | `docs/kalimba-disasm.md` |
| data_us word / period index | words of the `data_us` file; the staging study groups them in periods of 32 words | word `i` of `data_us` is fully writable iff `i % 32` is in 9..22 (14 words per 32-word period) | area bytes `600+2i` and `601+2i` (proven by script output, `payload-184.md`) | `docs/deep/offline-2026-10-10/payload-184.md` |

Notes that prevent mistakes (all proven unless marked):

- The assembler's word test `blind(cw) = 34 <= (2*cw + C0) % 64 <= 60` and `fsedit.py`'s byte test (34..62) agree: a word covers two bytes, so its low byte must be at 60 or below for the high byte to stay at 61 or below.
- Branch and `bsr` operands are relative to the LAST word of the instruction: `target = addr + nwords - 1 + operand` (`docs/deep/offline-2026-10-10/stack-transform.md` section 1, same rule as `tools/disasm.py`).
- "262" means two unrelated things: the stack headroom at hook `0xAE0` and `0xE46` (316 declared minus 54 on the deepest path = 262 words), and the retracted 262 "writable cave words" of the whole-pool scan that crashed probe130. Always say which. (`docs/cave-budget.md`)
- Two filesystem diff sizes appear: `975,168` bytes (marker-aligned whole fs area, the standard) and `974,538` (extracted files via csrdfu, one 2026-10-02 cycle). Either is valid; record which. (`docs/FLASH-PROTOCOL.md`)

## 2026-10-28 additions (probes 361-381)

- **AY batches A-D** - the owner-approved extra dead functions of the VM image (`CODE_REGION_AY` in `tools/caveguard.py`): A (3) and B (3) in use since 2026-10-24, C (`fn_2fde2`) and D (16 small functions) approved 2026-10-28 and proven inert hands-free by probe381. - **check digit** - the 7th spoken digit of a census word: the sum of the six octal digits mod 8.
- **GEN** - the build flag of the lean generator product (probe380): no recorded noise, a heartbeat poll instead of the chunk poll, the DSP program carried as a data table in the cave window. `build/hook/ladder_core.py`, `ladder_ext.py`.

- **heartbeat** - the 4 s message the lean product re-sends instead of a chunk poll: it re-asserts the level, cancels the stock timers and restarts the bring-up if the DSP vanished.
- **hook (timer)** - writing the generator's address into the tone-copy timer's handler cell (M[0x8367]); the unhook writes 0x16C3 back.

- **PM window** - the DM address range (0x020000 / 0x030000 / 0x040000 + PM address) through which the DSP's program memory is read and written once DM[0xFE65] = 1.
- **PM_WIN_ENABLE** - the DSP register 0xFFFE65 (the 16-bit form 0xFE65) that turns the PM window on; reads back 0.
- **ring (tone ring)** - the {size, rd, wr} structure at DM 0x2A73 the tone mixer reads; 256 samples by default, 512 in probe366/367.
- **safe ids** - console event ids in the default arm of the stock event switch (see F310).
