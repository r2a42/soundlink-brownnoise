## 0. How to use this file

1. Find the topic heading, read the rows, follow the source cell for detail. Never act on a row without opening its source if the action costs a flash.
2. Rows are one sentence each. IDs are F (fact), N (negative), Q (open question), X (retraction). They are assigned in file order; cite an ID together with its topic because a later edit may append rows.
3. Precedence when sources disagree: the amendment at `field-log.md:13674` and `docs/RETURN-CHECKLIST.md` section 6, then `docs/deep/offline-2026-10-10/verify.md` and `docs/deep/offline-2026-10-10/stack-transform.md`, then `docs/deep/offline-2026-10-10/DESIGN.md` section 8, then later field-log entries over earlier ones, then everything else. `build/hook/FLASHED` is authoritative only for what is on the speaker, not for claim grades.
4. Confidence marks. proven (press) = the owner heard it, quoted in the field log. proven (decode) = an instruction or address quoted from the disassembly. proven (readback) = flash read back and compared. proven (cmd output) = a tool printed it. proven (arithmetic) = reproducible computation. well-supported = static reading or ADK source, never pressed. hypothesis = stated as such by the source. unknown = no source answers it. A small n is written out, for example "n=2". A static stack-image reading is never "proven on hardware" until a press says so.
5. Ear-timed durations ("about 3 s") are estimates, not measurements.
6. Source notation. `field-log.md:NNNN` is a line of `docs/field-log.md` (13,714 lines, append-only, do not edit): usually the heading of the entry that holds the fact, sometimes a line inside it; open it with `sed -n NNNN,+40p`. Other cells name a file under `docs/`, `tools/` or `build/` and, where it helps, a section or line. "memory NAME" means the owner's auto-memory note `NAME.md`, kept machine-local outside the repo.
7. Companion files not to be confused with this one: `docs/field-log.md` is evidence, `docs/RESUME-HERE.md` is the live banner, `docs/FLASH-PROTOCOL.md` is the gate text, `docs/PROJECT-LAYOUT.md` is the file map.
